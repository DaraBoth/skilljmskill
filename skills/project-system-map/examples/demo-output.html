한눈에 보기At a glance

이 도구는 코드베이스 하나를 새 개발자가 처음부터 끝까지 읽고 믿을 수 있는 문서로 만들어요. 에이전트가 원본 파일을 쓰고, 스크립트가 인용과 설명을 검사한 뒤, 그림과 탭이 있는 HTML 한 장을 만들어요.

This kit turns one codebase into a document a new developer can read top to bottom and trust. The agent writes the source files, the scripts check the citations and explanations, and then build one HTML page with diagrams and tabs.

점선은 검사 결과가 에이전트에게 돌아가는 길이에요. 아이콘을 누르면 설명이 나와요. The dashed line is the problem list going back to the agent. Click an icon for its explanation. 전체 화면으로 열기Open full screen

What

원본 파일 몇 개가 검사와 빌드를 거쳐 문서 한 장이 돼요.

A few source files become one document after the checks and the build.

How

에이전트가 원본을 쓰고, 검사 스크립트가 인용과 설명을 확인하고, 빌드 스크립트가 HTML 을 만들어요.

The agent writes the sources, the check scripts verify citations and explanations, and the build scripts write the HTML.

Why

문서의 모든 말이 실제 코드 줄로 돌아갈 수 있어서 믿을 수 있어요.

Every claim leads back to a real line of code, so the document can be trusted.

파일 하나가 가는 길The path of one file

  1. 에이전트가 map-data.mjs 에 그림 상자와 선을 쓰고, 상자마다 설명과 코드 위치를 달아요.
  2. check-cites.mjs 가 모든 코드 위치를 고정한 커밋에서 확인해요 (check-cites.mjs:52-61).
  3. build-maps.mjs 가 그림마다 한국어와 영어 페이지를 그려요.
  4. build-page.mjs 가 탭을 모아 out/index.html 을 만들고, build-single.mjs 가 파일 하나로 묶어요.
  1. The agent writes the diagram boxes and lines in map-data.mjs, each with an explanation and its place in the code.
  2. check-cites.mjs checks every code location at the pinned commit (check-cites.mjs:52-61).
  3. build-maps.mjs draws a Korean and an English page for each diagram.
  4. build-page.mjs gathers the tabs into out/index.html, and build-single.mjs packs it into one file.

인용 형식Citation format

인용은 언제나 path:line 이나 path:from-to 예요. 읽는 곳은 lib.mjs:55-60 에 있어요.A citation is always path:line or path:from-to. It is read in lib.mjs:55-60.

설명을 찾는 순서Where explanations come from

상자의 info, 그다음 details.mjs, 마지막으로 map-explain.mjs 순서로 찾아요 (lib.mjs:106-121).First the box's own info, then details.mjs, then map-explain.mjs (lib.mjs:106-121).

빌드 순서Build order

스크립트는 언제나 같은 순서로 돌아요. 검사가 실패하면 그 자리에서 멈추고, 문제 목록을 출력해요.

The scripts always run in the same order. A failing check stops there and prints its problem list.

번호를 누르면 그 단계의 설명이 나와요. Click a number for that step's explanation. 전체 화면으로 열기Open full screen

What

스크립트를 도는 순서예요.

The order the scripts run in.

How

검사가 둘 다 통과한 뒤에 그림, 카드, 페이지, 파일 하나 순서로 만들어요.

After both checks pass, it builds the diagrams, the cards, the page and the single file, in that order.

Why

틀린 인용이나 빈 설명이 게시되기 전에 멈춰요.

A wrong citation or an empty explanation stops the run before anything is published.

명령Commands

node check-cites.mjs     # 0 problems
node find-empty.mjs      # every item has an explanation
node build-maps.mjs      # out/diagrams/*
node add-www.mjs         # What / How / Why rows
node build-page.mjs      # out/index.html
node check-tags.mjs      # all balanced
node build-single.mjs    # out/<singleFileName>

문서를 쓰는 에이전트The writing agent

문서를 쓰는 에이전트의 길이에요. 검사 두 개와 브라우저 확인이 갈림길이고, 실패하면 고친 뒤 같은 검사를 다시 돌려요.

The writing agent's path. Two checks and a browser look are the branches; on a failure it fixes the problem and runs the same check again.

마름모는 갈림길, 회색 테두리 상자는 끝이에요. Diamonds are decisions; the grey-bordered box is the end. 전체 화면으로 열기Open full screen

What

에이전트가 문서 하나를 끝내는 길이에요.

The path the agent takes to finish one document.

How

갈림길마다 고치고 같은 검사를 다시 돌려요.

At each branch it fixes the problem and runs the same check again.

Why

검사가 다 통과해야만 게시하기 때문에 문서가 코드와 어긋나지 않아요.

Publishing waits for every check, so the document cannot drift from the code.
